# system · 系统全貌

> **等级**：system（已实现现状）｜ **纪律**：只写"是什么、在哪、为什么这样设计（指向 decision）"；不写"怎么实现"（实现细节在代码，当次思路在 dev-notes）
> **读取方式**：按任务取读--先看下表决定读哪些，不要全量通读
> **红线**：单文件 ~300 行软红线；每文件尾部有同步戳；收尾时全量核对

## 系统一句话

微信公众号排版助手：Markdown / Word / 飞书内容 → 内联样式排版 → 一键复制进公众号编辑器（纯静态前端，与 CONSTITUTION §0 一致）。

## 文件导读

| 文件 | 内容 | 什么时候读 |
|---|---|---|
| `domain.md` | 业务关系、核心概念、术语表 | 理解业务语义、统一沟通用词 |
| `entities.md` | 对象/实体关系、字段、关联（ER 视角） | 改动涉及数据/对象结构时 |
| `modules.md` | 模块划分与依赖关系 | 定位改动位置、评估影响面 |
| `interfaces.md` | 对外接口与数据结构约定（剪贴板、CDN 依赖） | 改动涉及边界契约时 |

## 维护规则

- 新文件入导读表；文件被拆分/取代时更新本表（本文件为维护级，AI 可直接更新）
- 多端产品新增端时：modules.md 增加该端为顶级模块，interfaces.md 补端间契约
