# CONSTITUTION · 项目宪法

> **等级**：全项目最高约束，AI 与用户共同遵守
> **修订**：拍板级--任何修改须经用户确认（含教训回流）
> **读取**：每次开窗第一份必读文件；新 AI 接手第一件事 = 读本文件 + STATUS.md

---

## 0 · 项目定位

- **一句话定位**：微信公众号排版助手——把 Markdown / Word / 飞书文档转成带内联样式的公众号排版并一键复制；给内容创作者（用户本人）用；纯静态前端，浏览器本地运行，数据不上传。
- **交付形态**（可多选；多端产品的初始端在创建时勾选，后续端通过架构变更长出）：
  - ☑ 本地应用——**纯静态 Web 工具形态**：无服务端、无打包产物，本地 HTTP 服务（或直接开 HTML）即交付；`single-file.html` 为单文件分发形态
  - ☐ 移动应用（APK）
  - ☐ 命令行工具 / 脚本
  - ☐ 软件包 / 库（GitHub / npm 分发）
  - ☐ Web 服务（可上云--云部署延后，本地服务端不受限；启用云部署须走架构变更）

## 1 · 技术栈红线

- **技术栈**（单端产品直接填；多端产品按端分行）：
  - 全局：**原生 JavaScript (ES6+)**，无构建链、无框架、无 node_modules
  - Web 端：单页 `index.html` + `css/style.css` + `js/app.js`（逻辑）+ `js/themes.js`（主题数据）；第三方库一律 CDN 引入：mammoth 1.6.0 / marked 9.1.6 / clipboard.js 2.0.11 / DOMPurify 3.0.6 / highlight.js 11.9.0
- **依赖纪律（两档）**：
  - 小工具库：AI 可自主引入，当次 dev-notes 记录理由
  - 框架级 / 架构级依赖（打包器、前端框架、Node 服务端）：必须新增 decision + 用户拍板后才可用
- **一键命令**（统一放在根级 `scripts/`）：
  - 启动：`bash scripts/start.sh`（python3 http.server，默认 :8888）
  - 验证：`bash scripts/verify.sh`（完整性 + 引用一致性 + smoke）
  - 构建：无（纯静态即交付；`single-file.html` 即单文件分发形态）

## 2 · 仓库与目录

- **同库原则**：代码与 project-docs/ 同一仓库
- **配置与代码分离**：密钥、环境配置永不入仓库（本项目无服务端配置，暂无 .env；若未来引入，仓库只放 `.env.example`）
- **目录骨架**：

```
layout-assistant/
├── index.html            # 主入口（Markdown/飞书双模式 + 主题选择 + 复制）
├── css/style.css         # 界面样式（编辑器/工具栏，非微信内容样式）
├── js/app.js             # 应用逻辑：解析、预览、主题应用、复制、快捷键
├── js/themes.js          # WECHAT_THEMES 主题数据（9 款，内联样式）
├── single-file.html      # 单文件简化版（自包含，CDN 引库，独立维护形态）
├── docs/                 # 上游文档（INDEX / DEVELOPER_GUIDE）
├── scripts/              # start.sh / verify.sh
├── project-docs/         # 文档体系（本目录）
└── screenshot.png / LICENSE / README.md / .gitignore
```

## 3 · 质量纪律

- **验证基建先于业务功能**：一键验证脚本已落地（`scripts/verify.sh`），任何功能迭代后必须全绿
- **每任务自验**：AI 完成任务必须自跑验证，全绿才算完成
- **绿色主线**：只在验证全绿后提交；一任务一提交；提交即推送；迭代封板打 tag

## 4 · 三大行为条款（永久生效，不得删改）

### 4.1 禁止假设条款

需求存在多种合理解释或影响面不明时，必须停下提问，禁止自行假设后继续。
提问格式：① 哪里不确定 ② 倾向哪个理解及理由 ③ 等用户确认。

### 4.2 不降低标准条款

不得为了"完成用户指令"采用自己判断为次优的实现；发现用户指令与最佳实践 / 已有架构冲突时，必须指出并等待裁决。
**指出冲突不算违抗，不指出才是失职。**

### 4.3 阻塞条款

当剩余任务全部依赖未确认事项时，必须如实报告"所有剩余任务均被阻塞"并列出等待清单；禁止为避免"看起来闲着"而推进边缘工作。**边缘工作制造虚假进度，比停滞更有害。**

## 5 · 流程纪律

- **没有体系外的免费手改**：任何代码修改必须落在迭代体系内
- **微迭代通道**：快修 = 一行 prd + 单任务 todo + 全套四件套（成本约五分钟）
- **执行期约束**：同一时刻只有一个任务进行中；不顺手改无关代码、不顺手"优化"

## 6 · 文档纪律

- **文档是唯一真相源**：不依赖聊天记录恢复上下文
- **确定性等级**：draft（讨论中）-> prd（已定未做）-> system（已实现现状）；读任何文件先辨等级
- **最小文档纪律**：system/ 只写"是什么、在哪、为什么这样设计（指向 decision）"，不写"怎么实现"
- **单文件软红线 ~300 行**：超限在封板时拆分/精简，迭代中途不动
- **同步戳**：system/ 每文件尾盖戳（`> 同步：iter-NN · commit · 日期`）；收尾时全量核对
- **确认分级**：
  - 拍板级（用户确认才生效）：宪法修订、prd 定稿、system/ 结构级变更、决策入档
  - 维护级（AI 维护、全留痕）：STATUS、todo、dev-notes、draft/、system/ 现状同步
- **传承性**：decisions/、iterations/ 只增不改；被取代 = 新增文件标注"已被 NNN 取代"，不原地涂改

## 7 · 编码规范

- **命名**：JS 函数/变量 camelCase；主题 key 用小写拼音（chenlu/dushi/senxi/guochao/wabi/vintage/sketch/fresh/industrial）；CSS 类名 kebab-case
- **结构与数据分离**：`js/themes.js` 只放 WECHAT_THEMES 数据，不放逻辑；DOM 操作与事件绑定集中在 `js/app.js`
- **XSS 红线**：任何富文本/Markdown 产物写入 innerHTML 前，必须过 DOMPurify 清洗（现有机制，不得绕过）
- **CSP 纪律**：新增 CDN 源必须同步更新 index.html 的 CSP meta（script-src/style-src/img-src），库与白名单缺一不可
- **缓存戳**：改动 css/js 后，同步 bump index.html 引用上的 `?v=` 参数
- **单文件版纪律**：`single-file.html` 保持自包含（仅允许 CDN 外链），不引用本地 css/js
- **注释**：中文注释，写"为什么"优先于"是什么"
